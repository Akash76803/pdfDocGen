# PARITY-1 — Desktop vs API PDF Visual Parity

## Baseline

Compared the same Tax Invoice generated by:

- Desktop app export
- Salesforce -> API Gateway -> private Cloud Run -> native PDF renderer

The business data matches, but visual parity is not yet exact.

## Confirmed differences

1. Transparent decorative PNG artwork is composited onto black in the native PDF path, while Desktop export shows it against the white page.
2. A calculated taxable value can surface as a raw floating-point scalar (for example `12205.599999999999`) in native output instead of the Desktop-formatted value.
3. Currency/grouping presentation and some stroke/spacing metrics differ slightly.
4. Page 2 structure and overall document pagination already match closely.

## RCA 1 — transparent PNG background

The native PDF renderer normalizes PNG/WEBP images to JPEG. The conversion canvas was transparent and was encoded directly to JPEG. Transparent pixels can therefore become black during JPEG normalization.

### Fix

Before drawing the source image, paint the normalization canvas white in every supported path:

- OffscreenCanvas + createImageBitmap
- DOM canvas + createImageBitmap
- HTMLImageElement fallback

This keeps transparent artwork visually consistent with the Desktop white page.

## RCA 2 — calculated number formatting

The headless adapter stores document formulas as raw calculated fields and bound FIELD blocks do not currently carry a display format. The generic display layer intentionally preserves RAW numeric scalars for backward compatibility. This explains why native output can expose floating-point residue while Desktop raster export shows presentation formatting.

This numeric-formatting gap requires a narrowly scoped follow-up so we do not globally force two decimals on non-financial formulas.

## Acceptance plan

1. CI passes with the image-compositing fix.
2. Deploy/regenerate the exact same Tax Invoice payload.
3. Compare the new API PDF against the Desktop baseline.
4. Confirm the floral image no longer has a black background.
5. Implement a scoped formula-display formatting bridge for the remaining taxable/currency parity gap.
6. Re-run the same comparison and record final parity status.
